# Проверка аудиовыхода AutoMix

Сценарий генерирует пару WAV. На исходящей дорожке щелчки идут каждые 500 мс, на входящей — каждые 480 мс. У дорожек разные частоты щелчков и по одному маркеру с известной позицией. Исходящий бас звучит весь переход, входящий вступает на первой доле такта через 10 секунд от начала перехода по исходящей сетке. План фиксирует исходящую фразу 36–52 с, входящую 1,920–17,280 с и начальное отношение скоростей 0,96.

## Запись на Windows

Нужны Windows 11 с WASAPI process loopback (сборка 20348 или новее), 64-битный VLC, JDK 21, настроенная сборка Desktop, Python, NumPy и FFmpeg. Из корня репозитория в PowerShell:

```powershell
python -m pip install --target build/automix-output/python numpy process-audio-capture==1.0.0
$env:PYTHONPATH = (Resolve-Path build/automix-output/python).Path
python experiments/automix_output/probe.py generate build/automix-output/run
python experiments/automix_output/probe.py capture build/automix-output/run A
python experiments/automix_output/probe.py capture build/automix-output/run B
python experiments/automix_output/probe.py analyze build/automix-output/run/A/loopback.wav > build/automix-output/run/A/metrics.json
python experiments/automix_output/probe.py analyze build/automix-output/run/B/loopback.wav > build/automix-output/run/B/metrics.json
```

На каждый запуск используйте новый каталог. Захват идёт с аудиовыхода отдельной JVM через штатный `PlayerController` и libVLC. Он включает только звук синтетического тестового процесса. WAV показывает сигнал Windows до ЦАП и акустики. Журнал `platter.log` показывает фактическую точку старта, скорости, тип перехода и время передачи баса. В A бас передаётся в середине, в B — на первой доле устойчивого вступления. В обоих случаях одинаковы разметка, файлы, логика планирования и темпа. Добавьте `--baseline` к обеим командам `capture`, чтобы повторить замер с отключённой коррекцией фазы на приглушённой подводке.

## Чтение замеров

Анализ сопоставляет щелчки по порядковому номеру от отдельного маркера каждой дорожки и берёт пары в середине перекрытия, отступая по две доли от краёв. Отчёт содержит пропуски, покрытие и абсолютный p95 в миллисекундах. Знаковое смещение считается как «входящая минус исходящая». Отрицательный знак означает, что входящая дорожка опережает исходящую. Дрейф — наклон линейной регрессии знакового смещения в мс/с. Условие эксперимента — покрытие от 95% и p95 не более 20 мс. Таблица `bass_40_to_110_hz` показывает уровень низких частот по долям относительно исходящей дорожки в соло на 32–33 с.

Чтобы сравнить огибающую при вступлении баса на последней доле, добавьте `--terminal-bass` к `generate` и снимите A/B в новом каталоге. В этой синтетической паре исходящий бас звучит непрерывно, входящий появляется на последней доле, а A по-прежнему использует середину фразы. В `terminal_bass_40_to_110_hz` приведены уровень баса относительно соло и пиковая амплитуда полного сигнала в 100-миллисекундных окнах по обе стороны последней входящей доли. В контрольном захвате за 500–400 мс до стыка бас был на −38,76 дБ относительно соло в A и на −4,97 дБ в B. В первые 100 мс после стыка обе версии вернулись примерно к уровню соло. Покрытие составило 100%, абсолютный p95 составил 7,08 мс в A и 18,24 мс в B.

Генератор и анализ работают отдельно от захвата. Для сравнения с Android добавьте оба WAV в тестовую библиотеку и подайте клиенту разметку из `fixture.json` через тестовый `/rest/platterAutoMix`. Ответ должен содержать `subsonic-response.platterAutoMix.tracks` с объектами `outgoing` и `incoming` под соответствующими ID треков. Начните исходящую дорожку с 30 с. Запишите выход на устройстве или на внешнем рекордере и передайте WAV команде `analyze`. Android-вариант A собирается с `-PplatterBassMidpoint=true`, B — с настройкой по умолчанию. Для обычного Desktop A задаётся JVM-свойством `-Dplatter.automix.bassMidpoint=true`.
