# Журнал изменений Platter для Navidrome

Сервис читает SQLite Navidrome в режиме только для чтения и хранит свой журнал в отдельном файле. Запросы авторизуются через `getMusicFolders`. Журнал выдаёт изменения только по библиотекам, доступным этому пользователю. Для добавленных и изменённых треков сервис получает данные через `getSong`.

После первой синхронизации Platter сохраняет курсор вместе с добавленными, изменёнными и удалёнными записями. Android и Windows проверяют журнал при следующем поиске после минутного интервала. Если журнал недоступен на сервере, действует обычная синхронизация каталога. При истечении истории или изменении доступа к библиотекам клиент начинает с новой сверки. По умолчанию журнал хранит последние 100 000 событий.

## Запуск на сервере

Сервис использует Python 3.10+ и SQLite. Укажите внутренний HTTP-адрес Navidrome и доступный для чтения `navidrome.db`. Передайте каталог данных целиком, чтобы SQLite видел файлы WAL и SHM. Каталог журнала должен быть доступен для записи пользователю сервиса.

```sh
python3 journal.py \
  --navidrome-url http://127.0.0.1:4533 \
  --navidrome-db /path/to/navidrome/data/navidrome.db \
  --state /path/to/platter-state/journal.db
```

Для Docker соберите образ командой `docker build -t platter-navidrome-journal .` из этого каталога. Запустите его в сети Navidrome и прокси, передайте каталог данных Navidrome как `read_only`, подключите отдельный том для файла журнала и укажите `--listen 0.0.0.0` для доступа из этой сети. Если Navidrome расположен под префиксом, включите префикс в `--navidrome-url`.

Направьте запросы `/rest/platterTrackChanges` с того же адреса, который использует Platter, в порт журнала `4534`. Остальные запросы продолжают обслуживаться Navidrome. Для публичного и локального адресов Platter маршрут добавляется в оба прокси. Пример блока Nginx для запуска сервиса на том же хосте.

```nginx
location = /rest/platterTrackChanges {
    access_log off;
    proxy_pass http://127.0.0.1:4534;
}
```

При базовом пути `/music` используйте `/music/rest/platterTrackChanges`. Параметры запроса содержат данные авторизации Subsonic, поэтому доступ к маршруту следует публиковать через существующий HTTPS-прокси Navidrome.

## Проверка

На сервере `GET /rest/platterTrackChanges` с обычными параметрами авторизации Subsonic возвращает начальный курсор. В следующем запросе передайте `cursor`, чтобы получить изменения после него. Запись с `song` добавляет или обновляет трек, запись с `deleted: true` удаляет его из локального индекса. При `reset: true` поле `resetReason` принимает значение `scope` при смене доступных библиотек или `history` при сбросе курсора с прежним набором библиотек.

Из каталога сервиса запустите `python3 -m unittest -v`. Тесты проверяют добавление, изменение тегов, пометку отсутствующего файла, удаление строки из базы, смену доступных библиотек и продолжение после перезапуска.
