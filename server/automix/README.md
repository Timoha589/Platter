# Анализ структуры для автомикса Platter

Воркер читает библиотеку Navidrome, размечает части песен, удары и первые доли тактов с помощью All-In-One и HTDemucs. Для каждого Subsonic ID он хранит таймкоды в отдельном SQLite. Музыка и база Navidrome монтируются только для чтения. Модель и результаты переживают перезапуск в томе `state`.

## Установка на Linux

Понадобятся Docker Compose, рабочий NVIDIA-драйвер и NVIDIA Container Toolkit. Скопируйте каталоги `automix` и `navidrome-journal` рядом внутри `server`. В `server/automix` выполните `cp .env.example .env`.

| Переменная | Что указать |
| --- | --- |
| `NAVIDROME_DATA` | Каталог на хосте с `navidrome.db`, WAL и SHM |
| `MUSIC_DIR` | Каталог музыки на хосте |
| `NAVIDROME_MUSIC_ROOT` | Путь к этой же музыке в настройках библиотек Navidrome, обычно `/music` |
| `NAVIDROME_URL` | Адрес Navidrome из контейнера, включая префикс вроде `/music`, если он настроен |
| `AUDIOMUSE_URL` | Адрес существующего AudioMuse-AI из контейнера. Пустое значение оставляет автомикс на локальной разметке |
| `AUDIOMUSE_TOKEN` | API-токен AudioMuse-AI из его настроек, если включена авторизация |
| `AUDIOMUSE_SERVER` | Имя или ID нужного Navidrome в AudioMuse-AI. Пустое значение выбирает сервер по умолчанию |

Если есть библиотеки вне общего корня, добавьте для них тома только для чтения с теми же путями, что в Navidrome. Отдельный пароль для воркера не нужен.

Если Navidrome доступен только внутри Docker-сети, укажите `NAVIDROME_URL=http://navidrome:4533` с фактическим именем контейнера. Положите рядом `compose.override.yaml` и подставьте имя существующей сети вместо `navidrome_default`.

```yaml
services:
  automix:
    networks: [music]
networks:
  music:
    external: true
    name: navidrome_default
```

```sh
docker compose build
docker compose run --rm automix python worker.py benchmark --limit 100
docker compose up -d
docker compose logs -f automix
```

Первый запуск скачивает веса. Бенчмарк исключает один прогревочный трек и печатает время на трек и оценку для 90 000. Запускайте его без другого анализатора на той же GPU. Для быстрой проверки сборки можно начать с `--limit 3`. Доступ к карте можно проверить командой `docker compose run --rm automix nvidia-smi` после сборки.

## Данные и Smart Fade из AudioMuse-AI

Воркер добавляет BPM, тональность и энергию из пакетного `/api/sync` к готовой разметке только тех записей, которые видны пользователю Navidrome. Platter учитывает эти данные при выборе фразы. Для точной синхронизации он использует позиции битов. При недоступности AudioMuse-AI воркер отдаёт имеющуюся разметку.

FFmpeg измеряет громкость по времени и тихие отрезки в начале и конце записи. Для записей с готовой сеткой воркер добавляет эти данные по мере запросов. Пока измерение идёт, клиент получает существующую разметку и ждёт обновление в фоне. Platter использует профиль, чтобы при выборе фразы избегать провалов громкости. Если биты не сходятся, кроссфейд может пройти между слышимым концом одной записи и слышимым началом другой. Поток с ограничениями на перемотку воспроизводится с начала.

В том же декодировании, что даёт поправки к атакам ударов (`beatOffsetsMs`), FFmpeg измеряет низкие частоты. Необязательное поле `bassEntries` содержит версию алгоритма и список первых долей тактов, где после более тихого участка появляется устойчивый бас или бочка. Текущая версия `{"version": 2, "downbeatsMs": [...]}` допускает синкопы и короткий затакт. Воркер обновляет старые записи по мере запросов, сразу возвращает готовую сетку и отмечает обогащение в `pending`. Клиенты принимают версии 1 и 2 и передают бас на подходящей доле внутри уже выбранной фразы. Подтверждённая метка версии 2 на последней доле также подходит, если измерения показывают активный исходящий инструментальный участок. В этом случае клиент дольше сохраняет его бас, завершает затухание на исходной границе и возвращает входящему треку полное усиление к этой доле. При отсутствии подходящей метки бас передаётся в середине. Журнал различает отсутствующее поле, неподдерживаемую версию, пустой анализ и отсутствие метки внутри выбранной фразы.

Если AudioMuse-AI опубликован только на loopback хоста, подключите воркер к Docker-сети AudioMuse-AI и укажите его имя сервиса и порт внутри сети.

Команда без аргументов проверяет версию AudioMuse-AI. С двумя ID Navidrome она показывает признаки треков и план Smart Fade в заданном порядке. Для сравнения используйте точку входа, длительность и пару из журнала Platter.

```sh
docker compose exec automix python audio_muse.py
docker compose exec automix python audio_muse.py OUTGOING_ID INCOMING_ID
```

Проверка плана рассчитана на AudioMuse-AI 3.7.3 с включённым Neural Fingerprint и готовым анализом пары.

## Подключение Platter

Проксируйте ровно `/rest/platterAutoMix` на воркер. Пример для Nginx, который запущен на том же хосте, что Docker.

```nginx
location = /rest/platterAutoMix {
    access_log off;
    proxy_pass http://127.0.0.1:4535;
}
```

С префиксом `/music` маршрут будет `/music/rest/platterAutoMix`. Если Platter подключён к прямому порту Navidrome, укажите в приложении адрес прокси, который пересылает этот маршрут в воркер, а остальные запросы в Navidrome. Для прокси в общей Docker-сети направьте запросы на `http://automix:4535`. Для удалённого доступа используйте существующий HTTPS-прокси Navidrome. Воркер проверяет Subsonic-авторизацию и доступ к библиотекам.

В Windows и Android выберите «Автомикс» в настройках. Platter запрашивает текущий трек и до двух следующих по ID. Когда домашний адрес не обслуживает маршрут анализа, Platter запрашивает разметку через основной адрес. Если анализа ещё нет, сервер ставит треки в приоритетную очередь, а приложение ждёт готовых таймкодов в фоне. Воспроизведение продолжает идти. Когда есть разметка, Platter может включить конец вступления перед куплетом или припевом и подвести переход к первой доле. На таймлайне участок сведения по битам выделяется синим. Если таймкодов к переходу ещё нет, работает обычный кроссфейд.

`SCAN_LIBRARY=0` обрабатывает треки по запросу. `SCAN_LIBRARY=1` добавляет обход всей библиотеки между приоритетными запросами. После смены значения запустите `docker compose up -d`. Уже обработанные записи берутся из кэша. Треки, которые завершились ошибкой, можно будет повторно обработать через час.
